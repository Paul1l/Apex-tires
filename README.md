# APEX WHEELS

## Открыть сайт

**[Перейти в интернет-магазин APEX WHEELS](https://apex-wheels-store.apex-barnaul.workers.dev)**

SPA-витрина интернет-магазина шин и дисков с фильтрами по размеру и
автомобилю, отдельной админкой, регистрацией, корзиной, юридическим разделом и
API-контуром обмена с 1С. Город магазина — Барнаул; способы и территория
доставки не публикуются до подтверждения владельцем.

## Запуск

```bash
pnpm install
pnpm dev
```

Магазин: `http://localhost:3000`  
Админка: `http://localhost:3000/admin`

Серверные API запускаются вместе с Next.js. PostgreSQL и интеграционные
переменные настраиваются по `.env.example`.

## Статус

Это публичный интерактивный прототип, не готовый принимать реальные заказы.
В режиме preview демонстрационный каталог и гостевая корзина сохраняются в
`localStorage` браузера и явно помечены как некоммерческие. В
режиме `database` витрина загружает товары только из PostgreSQL через server
API. Покупательская авторизация переведена на серверный email OTP, но на
стенде она останется отключенной до подключения БД и ключей Yandex Cloud
Postbox. Production-схема находится в PostgreSQL-миграциях, но развернутой
production-БД в репозитории нет.

Для 1С подготовлен server-side integration layer внутри Next.js. Реальное
соединение остается выключенным до получения параметров конкретной базы 1С.

## Реализовано

- каталог шин и дисков, поиск, сортировка и фильтры;
- поиск по широкому справочнику марок и моделей с учетом года;
- прокручиваемые списки марок и моделей с фильтрацией по первым буквам;
- отдельный импорт точной применяемости товаров из 1С;
- избранное, сравнение и корзина;
- вход и регистрация по 6-значному коду из письма, серверная сессия;
- запрет `@gmail.com` и `@googlemail.com` на сервере и в интерфейсе;
- server-side защищённая админка для ролей manager/admin;
- CSV-import товаров и применяемости с частичным отчетом ошибок;
- чтение реальных заказов и изменение статусов с audit log;
- отдельные правовые документы и согласия в формах;
- cookie-центр: Метрика не загружается до согласия;
- runtime-настройка `YANDEX_METRIKA_COUNTER_ID`;
- версионированный JSON API 1С для товаров, цен, остатков и заказов;
- `ERPIntegrationProvider` / `OneCProvider` / `OneCHttpProvider`;
- идемпотентные batch, журнал ошибок и надежная очередь заказов;
- PostgreSQL-миграции и серверный слой Next.js;
- потоковый CSV-импорт до 300 000 строк, транзакции по 100–2000 строк; локально испытано 50 000 SKU;
- единая business-конфигурация, проверка реквизитов и блокировка незаполненного production-деплоя;
- гостевой checkout, настраиваемые способы получения и опциональный шиномонтаж;
- модели новых/б/у товаров, отдельные б/у комплекты и индивидуальные фото;
- страница контактов, безопасная ссылка на 2ГИС, локальные metadata/robots/sitemap;
- заявка «Не нашли автомобиль?» с хранением в PostgreSQL;
- контракты `FitmentProvider`, `PaymentProvider`, `NotificationProvider`;
- постоянная корзина зарегистрированного пользователя и история заказов;
- Docker Compose, Nginx/HTTPS и backup-заготовка для российского VDS;

## Production checklist

1. Получить реквизиты ИП и провести юридическую проверку документов.
2. Разместить Next.js и PostgreSQL в РФ; применить production-миграции.
3. Подключить production PostgreSQL; каталог, CSV-import, корзина, заказы и
   административные статусы уже имеют защищённый server API.
4. Подключить email OTP к российской БД и Yandex Cloud Postbox, проверить
   rate limit и доставляемость.
5. Подключить объектное хранилище фотографий.
6. Настроить эквайринг, онлайн-кассу, доставку и уведомления.
7. Получить данные о конфигурации 1С и разработать расширение/обработку.
8. Задать секрет обмена и включить регламентные задания после staging-теста.
9. Создать счетчик Метрики и задать `YANDEX_METRIKA_COUNTER_ID`.
10. Выполнить нагрузочные, security, backup/restore и приемочные тесты.
