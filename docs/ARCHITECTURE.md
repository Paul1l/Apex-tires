# Архитектура APEX WHEELS

## Текущее состояние

Проект — функциональный закрытый прототип на Next.js. Витрина, фильтры,
корзина, регистрация, редактирование товаров и загрузка изображений работают в
браузере. Эти данные сохраняются в `localStorage` конкретного устройства и не
попадают в серверную базу.

Опубликованный стенд нельзя использовать для реальных регистраций, заказов и
платежей. Причины:

1. нет production-базы и серверных репозиториев;
2. демо-авторизация не является production-аутентификацией;
3. нет онлайн-кассы, эквайринга и службы доставки;
4. реквизиты продавца и оператора ПД еще не заполнены;
5. не выбрано российское место первичного хранения персональных данных.

## Модули

| Модуль | Назначение |
| --- | --- |
| `app/page.tsx` | входная страница магазина |
| `components/storefront.tsx` | SPA-витрина, фильтры, карточки, корзина и формы |
| `components/admin-dashboard.tsx` | демонстрационная панель товаров |
| `components/store-provider.tsx` | браузерный адаптер каталога, аккаунтов и корзины |
| `components/privacy-tools.tsx` | cookie-центр и условная загрузка Яндекс Метрики |
| `app/legal/**` | индекс и страницы юридических документов |
| `app/api/1c/[...action]/route.ts` | защищенный JSON API обмена с 1С |
| `database/schema.sql` | референсная SQLite/D1-схема |
| `lib/db/schema.ts` | типизированное описание той же схемы для Drizzle |

## Целевая production-схема

```text
Браузер
  ├─ статическая витрина / Next.js
  └─ HTTPS-запросы с ПД ──> API в РФ
                              ├─ PostgreSQL в РФ
                              ├─ объектное хранилище фото
                              ├─ платежи / онлайн-касса / доставка
                              └─ шлюз обмена <──> 1С
```

Рекомендуемый вариант — размещать весь сервер приложения и PostgreSQL в
российском дата-центре. Если витрина остается на глобальном edge-хостинге,
формы с персональными данными должны отправляться напрямую в российский API, а
договоры с подрядчиками и фактические потоки данных нужно проверить отдельно.

## Что заменить перед запуском

1. Создать интерфейсы репозиториев `ProductRepository`, `UserRepository`,
   `OrderRepository` и их PostgreSQL-реализации.
2. Заменить `StoreProvider` на запросы к API; оставить в браузере только
   временное состояние корзины и настройки cookie.
3. Реализовать серверную сессию в `HttpOnly`, `Secure`, `SameSite` cookie.
4. Хешировать пароль на сервере Argon2id; добавить rate limit, CSRF-защиту,
   восстановление пароля и журнал административных действий.
5. Хранить фото в объектном хранилище, в БД — только URL, alt и порядок.
6. Создавать заказ транзакционно: `orders` и `order_items`, затем передавать его
   в 1С.
7. Подключить мониторинг, резервные копии, миграции и тестовое окружение.

## Правила понятного кода

- функции называются по действию: `authorizeOneCRequest`,
  `recordSuccessfulSynchronization`;
- булевы значения формулируются как утверждение: `analyticsAllowed`,
  `databaseConfigured`;
- идентификаторы содержат сущность: `productId`, `synchronizationId`, а не
  `id` вне короткого локального контекста;
- преобразование данных отделяется от сетевых и SQL-операций;
- комментарий объясняет причину или ограничение, а не повторяет строку кода;
- публичные функции и нетривиальная безопасность описываются JSDoc;
- деньги хранятся целым числом в копейках, время — ISO 8601 UTC;
- внешние идентификаторы 1С хранятся отдельно от внутренних UUID.
