# Импорт товаров

Шаблон: `docs/examples/products-import.csv`. Его строки — явно неактивные
примеры. Не загружайте пример как коммерческий ассортимент.

Администратор/менеджер отправляет UTF-8 CSV с запятыми через раздел «Товары».
API: `POST /api/admin/imports/products`, Content-Type `text/csv`,
`X-File-Name` — encodeURIComponent имени, `X-Import-Mode` — incremental/full.
Авторизация — серверная сессия, никаких API-ключей в браузере.
Сторонний Origin отклоняется. Multipart ограничен 10 МБ, потоковый CSV —
200 МБ и 300 000 строк. `CATALOG_IMPORT_BATCH_SIZE` — 100–2000, по умолчанию 1000.

Обязательные заголовки: external_id, sku, name, brand, model, kind, diameter,
price. kind=tire/wheel. Шине нужны width/profile/diameter/season; сезон:
summer/winter/all-season. Диску нужны wheel_width/bolt_count/pcd (число),
offset (ET), center_bore (DIA) при наличии. Текстовый pcd можно сочетать с
отдельным числовым pcd_number. Булевы значения: true/false, 1/0, yes/no, да/нет.
Необязательные числовые ячейки пустые; N/A и произвольные строки — ошибки.
Для stock нужны warehouse_code и warehouse_name; warehouse_external_id
по умолчанию совпадает с кодом. Отсутствующий stock не перезаписывает остаток.

Цена — рубли с точностью до копейки, в БД хранится BIGINT в копейках. Отрицательные
цены/остатки отклоняются. old_price необязательна, скидку сайт не выдумывает.
image_url сохраняет URL, файл не скачивается в БД и не преобразуется в base64.
Допустимы только адреса `https://…` (без логина и пароля в URL) или пути от корня
сайта `/…`; `http:`, `data:`, `javascript:` и `file:` отклоняются при импорте.

Приоритет поиска: source_system+external_id, затем SKU. Внешний источник CSV
равен csv. Повтор файла обновляет строки; повтор external_id/SKU внутри файла
попадает в отчёт. Товар с владельцем 1c нельзя перезаписать CSV. Slug сохраняется
при изменении цены/названия. Конфликт разных внешних идентификаторов одного SKU
возвращается как ошибка, а не создаёт второй товар.

Пакет сохраняется transaction, отдельная запись — savepoint. Валидные записи
не откатываются из-за ошибочной соседней строки. Синтаксически повреждённый
CSV/обрыв потока прерывает дальнейшую обработку; уже завершённые пакеты остаются.
Повторите исправленный файл. Парсер обрабатывает кавычки, переносы строк и
границы UTF-8 чанков. XLSX пока не поддерживается.

Full деактивирует отсутствующие товары только источника csv и только при
непустом, полностью успешном импорте. При ошибках деактивации нет. Перед full
нужно проверить полноту файла: это снимок всего CSV-ассортимента.

`import_jobs` хранит число прочитанных/обработанных строк, созданных, обновлённых
и ошибок. До конца потока total_rows — прочитанное количество, не предсказанный
размер файла. `GET /api/admin/imports/jobs` обновляет журнал в админке.
`GET /api/admin/imports/jobs/{uuid}/errors` скачивает все ошибки потоковым CSV.
JSON-ответ импорта ограничен первыми 100 ошибками. Формулы в error CSV экранируются.

Статус «Прерван» (`failed`) и зависшие задания. Если импорт прерывается
(обрыв соединения, перезапуск PostgreSQL), итоговый статус `failed` пишется с
повторами, пока база недоступна: паузы 1, 2, 4, 8 и 15 с, все попытки — не
дольше ~45 с. Поэтому CLI и HTTP-запрос завершаются за ограниченное время и не
висят. Если записать статус так и не удалось (процесс убит, база недоступна
дольше), задание закрывается по порогу. Признак работы — колонка
`last_progress_at` (миграция `008_import_job_progress.sql`, нужен
`pnpm db:migrate`): она обновляется при старте импорта и с каждым
зафиксированным пакетом. Задание `queued` или `processing` без признаков работы
дольше `IMPORT_JOB_STALE_MINUTES` (1–1440, по умолчанию 30) получает `failed`
с причиной «Импорт прерван: нет признаков работы N мин.». Проверка выполняется
при чтении журнала в админке (`GET /api/admin/imports/jobs`) и перед стартом
каждого нового импорта (админка и CLI). Живой импорт фиксирует пакет за
секунды, поэтому его проверка не трогает. Исключение — если один пакет дольше
порога ждёт блокировку в базе. Тогда задание временно покажется прерванным,
а итоговый статус после завершения импорта перезапишет отметку.

Импорт исполняется в HTTP-запросе, а не в независимом durable worker.
Nginx для import URL настроен на 200 МБ и 3600 секунд. Для наиболее больших
файлов есть операторский CLI `pnpm import:csv products path.csv` (на VDS без
pnpm, с подключением файла — `docs/VDS_DEPLOYMENT.md`, «Команды без pnpm»); он
использует тот же сервис и не зависит от таймаута браузера. Рестарт процесса требует
повторной отправки файла. Возобновление с произвольной строки не реализовано.

Витрина: импорт через админку сразу сбрасывает кэш главной, `/shiny` и
`/diski` (страницы товаров кэша не имеют). CLI работает вне процесса Next.js,
поэтому после него каталог на этих страницах обновляется в течение 5 минут;
немедленный сброс — `sh deploy/scripts/run-internal-job.sh catalog-revalidation`
(защищённое задание `POST /api/internal/jobs/catalog-revalidation` с
`X-Job-Key`), см. «Обновление витрины после импорта» в `CSV_IMPORTS.md`.

Публичный каталог (`/api/v1/products`, страницы витрины, корзина) не отдаёт
`external_id` и точные остатки: при режиме `NEXT_PUBLIC_AVAILABILITY_DISPLAY_MODE`,
отличном от `exact`, поля `stock`/`reserved` содержат только значения, нужные
для надписи наличия (`reserved = 0`; `stock` = 0, если свободного остатка нет,
иначе 1, а для `limited` — 1 для «Мало» и 5 для «В наличии»). Точные значения
видны в админке (`/api/admin/products`), заказ резервирует реальный остаток.
