# Редактор каталога в админке

Менеджер и администратор (`manager`, `admin`, вход сотрудника по коду из
приложения — `docs/AUTHENTICATION.md`) создают и меняют товары без CSV:
карточка, характеристики, цена, остатки по складам, фото, применимость к
автомобилям, бренды и категории. Все изменения пишутся в `admin_audit_log`,
витрина обновляется сразу после сохранения.

## Список товаров

Админка → «Товары». Поиск по SKU, артикулу, названию, модели и бренду (часть
строки, без учёта регистра), фильтры «Активные / Неактивные / Все», источник
(вручную, CSV, 1С), шины/диски, страницы по 24 строки. В списке видны и
товары без цены (на витрине их нет). Кнопка «Добавить товар» открывает
`/admin/products/new`, «Изменить» в строке — `/admin/products/<id>`.
Массовые действия (только `admin`) и импорт CSV работают как раньше.

## Создание товара

Обязательно: тип (шина или диск — после создания не меняется), SKU (уникален
без учёта регистра), название, бренд, модель, посадочный диаметр.

- Шина: ширина и высота профиля, сезон; по желанию шипы, RunFlat, XL,
  индексы нагрузки и скорости.
- Диск: ширина (J), количество отверстий, PCD; по желанию вылет ET,
  центральное отверстие DIA, тип и цвет.

Кнопка «Собрать название…» предлагает название из бренда, модели и размера.
Размеры пишутся и в `products`, и в `tire_specs`/`wheel_specs` — по ним
работают фильтры каталога и подбор по автомобилю. Адрес страницы (slug)
создаётся один раз из названия и SKU тем же правилом, что при импорте, и
дальше не меняется. Новый товар получает источник «вручную» (`manual`).

Цена и остатки задаются сразу или позже. **Без цены товар не показывается в
каталоге.** «Показывать на сайте: нет» скрывает товар; товары не удаляются.

## Редактирование

Форма отправляет только изменённые поля. Сохранение карточки, цены и
остатков — одна транзакция: при ошибке не сохраняется ничего.

**Одновременные правки.** Форма помнит версию товара (`products.updated_at`).
Если товар изменили после открытия формы (другой сотрудник, импорт CSV, обмен
с 1С), сохранение отклоняется (`409 PRODUCT_VERSION_CONFLICT`) с предложением
загрузить актуальные данные.

**Товары из CSV** можно править, но следующий импорт этого товара
перезапишет карточку, цену и переданный в файле остаток (`docs/DATA_OWNERSHIP.md`).

### Цена

В форме — рубли (`12 990` или `12 990,50`), в базе — копейки. Цена больше
нуля; старая цена необязательна и должна быть больше текущей (скидка
считается от неё). Удалить цену у товара нельзя — чтобы убрать товар с сайта,
снимите «Показывать на сайте».

### Остатки

Таблица показывает все активные склады: остаток, резерв, свободно. Остаток —
физическое количество. **Его нельзя сделать меньше резерва**: эти единицы уже
в заказах (`422 STOCK_BELOW_RESERVED`, сообщение называет склад и резерв).
Резерв меняется только заказами. Склады создаются импортом CSV (колонки
`warehouse_code`, `warehouse_name`) или обменом с 1С; в админке их список
только читается. Пока складов нет, остатки задать нельзя.

## Товары из 1С

Обмен с 1С (`ProductRepository.upsertFromExternalSystem`, `upsertPrice`,
`upsertStock`) записывает у товаров с источником `1c`:

| Данные | Кто меняет |
|---|---|
| Вся карточка: SKU, артикул, название, бренд, модель, категория, описание, страна, активность, размеры и свойства | только 1С |
| Розничная цена и старая цена | только 1С |
| Остатки по складам | только 1С |
| Фото, пришедшие из 1С | только 1С (заменяются каждым обменом) |
| Фото, добавленные на сайте | админка — обмен их не трогает; они идут после фото из 1С |
| Применимость к автомобилям (`fitments`) | админка — 1С эту таблицу не заполняет |

В редакторе закрытые поля недоступны, а сервер отклоняет их изменение
(`409 PRODUCT_SOURCE_CONFLICT`) — даже если запрос отправлен в обход формы.
Сохранение без фактических изменений проходит.

## Фото

Блок «Фотографии» на странице товара (после создания).

- **Загрузка файла**: JPEG, PNG, WebP. Тип определяется по содержимому файла
  (сигнатура), имя файла и тип из браузера не учитываются; SVG, HTML и всё
  остальное отклоняется (`415 UNSUPPORTED_IMAGE_TYPE`). Лимит размера —
  `PRODUCT_IMAGE_MAX_BYTES` (по умолчанию 5 МБ, `413 IMAGE_TOO_LARGE`).
- **По ссылке**: только `https://…` без логина и пароля; файл не скачивается.
- Не больше `PRODUCT_IMAGE_MAX_COUNT` фото у товара (по умолчанию 10).
- **Порядок**: первое фото — главное, его показывают каталог и страница
  товара. Стрелки меняют порядок, «Сохранить порядок и подписи» записывает
  порядок и подписи (alt).
- **Удаление** убирает запись; файл удаляется с диска, только если сайт сам
  его сохранил для этого товара (`products/<id>/<случайное имя>`). Ссылки на
  другие сайты и файлы из CSV/1С не трогаются.

Хранение: `UPLOADS_DIR/products/<id товара>/<32 случайных hex>.<jpg|png|webp>`,
адрес на сайте — `/uploads/products/<id товара>/<файл>`, в базе —
`product_images.url` и `storage_key`. Маршрут `/uploads/...` отдаёт только
файлы такого вида (без `..`, кодированных разделителей, NUL, символических
ссылок за пределы каталога), с фиксированным `Content-Type`,
`X-Content-Type-Options: nosniff` и `Cache-Control: public, max-age=31536000,
immutable` (имена не повторяются). Всё остальное — 404.

Код файлового хранилища — `server/storage/` (локальный каталог за небольшим
интерфейсом `ImageStorage`; хранилище S3 можно добавить позже, не меняя
сервисы).

### Настройка UPLOADS_DIR

| Переменная | Значение |
|---|---|
| `UPLOADS_DIR` | абсолютный путь к постоянному каталогу, доступному приложению на запись. Пусто — загрузка выключена (фото по ссылке работают, в редакторе — пояснение) |
| `PRODUCT_IMAGE_MAX_BYTES` | 100000–20000000, пусто = 5242880 (5 МБ) |
| `PRODUCT_IMAGE_MAX_COUNT` | 1–30, пусто = 10 |

Неверное значение не останавливает сайт: загрузка выключается, редактор
показывает, какая переменная задана неверно.

Для VDS (Docker): каталог должен быть томом, иначе фото пропадут при
пересборке контейнера, и принадлежать пользователю приложения (`apex`,
uid 10001). Тело запроса загрузки ограничено nginx `client_max_body_size 6m`:
при `PRODUCT_IMAGE_MAX_BYTES` больше ~5,9 МБ лимит nginx нужно увеличить.
Том с фото входит в резервное копирование наравне с базой. На Cloudflare
Workers постоянного диска нет — там `UPLOADS_DIR` не задаётся.

## Применимость к автомобилям

Подбор по автомобилю на витрине связывает **поколение (или модификацию)
автомобиля с размером** (таблица `fitments`), а не с конкретным товаром:
товар подходит, если его размер из `tire_specs`/`wheel_specs` совпадает с
проверенной (`verified`) записью. Поэтому блок «Применимость» показывает и
меняет записи по размеру товара, и изменение действует на все товары того же
размера (их число показано). Старая таблица `product_fitments` (протокол 1С)
витриной не используется и здесь не редактируется.

- **Добавить**: марка → модель → поколение → модификация (или «все»), ось,
  тип. Для дисков можно ограничить ET (от/до) и DIA ступицы; сервер
  проверяет, что сам диск в этот диапазон попадает. Запись создаётся с
  источником «вручную» и сразу подтверждена; повтор не создаёт дубль.
- **Отозвать**: запись становится неподтверждённой (`verified = false`) и
  перестаёт действовать; строка сохраняется для истории и может быть
  подтверждена снова.
- Марки, модели и поколения берутся из справочника, который заполняет импорт
  `fitments.csv` (`docs/FITMENT_IMPORT.md`). Пока справочник пуст, добавить
  применимость нельзя — редактор об этом сообщает.

## Бренды и категории

В карточке товара: выбор из списка или «+ Новый бренд» / «+ Новая категория».
Если бренд или категория с таким названием (без учёта регистра) уже есть,
используется существующая запись. Slug бренда строится тем же правилом, что
при импорте, поэтому импорт CSV/1С с тем же брендом использует ту же запись.
Удаления нет. Отключённые бренды и категории в новых товарах выбрать нельзя.

## Витрина и журнал

После каждого успешного изменения сбрасывается кэш `/`, `/shiny`, `/diski` и
страницы товара (`/tires/<slug>` или `/wheels/<slug>`); страницы товаров и так
строятся на каждый запрос.

Записи `admin_audit_log`: `catalog.product.created`, `catalog.product.updated`
(список изменённых полей, цена «было/стало», остатки «было/стало»),
`catalog.product.image_uploaded`, `catalog.product.image_linked`,
`catalog.product.images_updated`, `catalog.product.image_deleted`,
`catalog.fitment.added`, `catalog.fitment.revoked`, `catalog.brand.created`,
`catalog.category.created`.

## API

Все маршруты — сессия сотрудника (`manager`/`admin`), изменения — с проверкой
Origin; ответы `Cache-Control: private, no-store`; без PostgreSQL — `503`.

| Метод и путь | Назначение |
|---|---|
| `GET /api/admin/products?search=&type=&active=true\|false\|all&sourceSystem=&page=&pageSize=` | список (pageSize до 100) |
| `POST /api/admin/products` | создать: `{card, price?, stock?}` |
| `GET /api/admin/products/{id}` | данные редактора, версия, закрытые поля, настройки загрузки |
| `PATCH /api/admin/products/{id}` | `{version, card?, price?, stock?}` — только изменённые поля |
| `POST /api/admin/products/{id}/images` | multipart `file`, `alt` — загрузка; JSON `{url, alt}` — ссылка |
| `PATCH /api/admin/products/{id}/images` | `{images: [{id, alt}]}` — порядок и подписи |
| `DELETE /api/admin/products/{id}/images/{imageId}` | удалить фото |
| `GET/POST /api/admin/products/{id}/fitments` | применимость товара / добавить |
| `DELETE /api/admin/products/{id}/fitments/{fitmentId}` | отозвать |
| `GET /api/admin/products/vehicle-references?level=makes\|models\|generations\|modifications&parentId=` | справочник автомобилей |
| `GET/POST /api/admin/brands`, `GET/POST /api/admin/categories` | бренды, категории |
| `GET /api/admin/warehouses` | активные склады (чтение) |
| `GET /uploads/products/{id}/{файл}` | публичная раздача загруженных фото |

## Известные ограничения

- Витрина показывает только первое фото и подписывает его названием товара;
  остальные фото и alt хранятся для будущей галереи.
- Индексы нагрузки и скорости (`tire_specs`) и ширина диска (`wheel_specs`,
  по ней работает фильтр) сохраняются, но страница товара их пока не
  показывает: она разбирает только строку размера («205/55 R16», «R18 5x112»).
- Склады в админке не создаются; марки и модели автомобилей — только из
  `fitments.csv`.
- Смена владельца товара (manual/csv → 1С) — по `docs/DATA_OWNERSHIP.md`, не в
  редакторе.
