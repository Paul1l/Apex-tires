# Источники данных и конфликты

Внутренний UUID сайта отличается от external_id. Источники: manual, csv, 1c.
Товар сопоставляется сначала по source/external, затем по SKU. Название не ключ.

CSV управляет импортируемой карточкой, ценой и явно переданным остатком.
Товар, уже принадлежащий 1c, запрещено менять CSV и массовыми ручными действиями.
Массовая активация/скрытие/смена категории/бренда ограничена 100 UUID, только
admin, confirmed=true, audit log. Массового hard delete нет.
Переход manual/csv → 1c должен быть согласован с владельцем до подключения;
адаптер обязан сопоставить GUID/SKU и проверить конфликтующие записи.

Неизвестные SKU/GUID, конфликт уникальности и неизвестная категория/бренд
выдают ошибку. Протокол не делает silent merge двух карточек с разными ключами.
product_external_ids подготавливает внешние связи, но универсальный UI смены
владельца и ручной override ещё не реализованы.

CSV/1С price — абсолютное значение, не дельта. stock.quantity — физический
остаток; stock.reserved — внешние резервы, НЕ включающие локальные активные
резервы сайта. Upsert добавляет локальные inventory_reservations и отклоняется,
если итоговый резерв превышает physical quantity. Это правило обязательно
согласовать с 1С: после выгрузки заказа нельзя учитывать один резерв дважды.
Реальная синхронизация и передача владения резервом в ERP пока не подключены.

Строка заказа snapshot-ит SKU, название, цену и характеристики. Цена/остаток
браузера не доверенные. Оформление, резерв, order_items, очередь 1С и очередь
уведомлений сохраняются одной транзакцией. Повтор checkout key возвращает
созданный заказ. Номер централизован: ORDER_NUMBER_PREFIX-год-последовательность.

Локальные резервы имеют TTL ORDER_RESERVATION_TTL_HOURS (технический default 24).
Периодический POST /api/internal/jobs/reservations с X-Job-Key освобождает до
100 истёкших заказов за вызов. Запускать до исчерпания очереди по мониторингу.
Отмена освобождает резерв, shipped/completed списывает физический остаток.
Повтор статуса не списывает дважды. Истёкший резерв не разрешает отгрузку:
менеджер проверяет наличие и оформляет новый заказ, старый отменяет.
TTL — не опубликованное условие продажи; согласуйте правила до запуска.

Кэш: цены/остатки и авторизованные ответы читаются заново; Redis отсутствует.
Sitemap — страницы по 5000 URL, HTTP cache 5 минут / shared cache 1 час.
Фасеты пока запрашиваются из БД, что видно в локальных замерах. При дальнейшем
росте следует добавить отдельный краткоживущий кэш справочников, не цен.
